# Four real-project A/B/C diagnostic

This diagnostic asks whether the complete frozen `/harness-task` delivers better
changes than ordinary OpenCode and an ordinary additional author pass. It uses
four existing VibeRacing connector snapshots; it is not a confirmatory sample.
The historical 100-pair and completed 20-pair comparisons remain unchanged.

Candidate: `66b7b33fc6bd66201ee24ec84d6e6fcae9daaf28`. Its runtime, prompts and
completion rules are frozen throughout this comparison. No model execution took
place during task selection, reference preparation or preflight.

`selection.json` fixes the public repository commit/tree for each task, the full
12-slot schedule and common OpenCode 1.18.26 / openai/gpt-5.6-luna / low settings.
Each task directory contains the full original prompt. The four tasks exercise:

- A protocol error API through pairing, reconciliation and usage consumers.
- Legacy runtime migration, ownership rejection, repeat loading and installation.
- Revoked authorization recovery through the real `connect` command.
- HTTP request/retry extraction with public behavior and installed runtime intact.

A is ordinary OpenCode. B starts independently and receives the exact text in
`B-CONTINUATION.txt` once, through its original native session, after its first
completion. C executes the complete candidate `/harness-task`. A single 900-second
deadline includes every phase, command and correction in each arm. Original
project instructions, source snapshots and available Node tools are the same.
Required targeted connector tests are specified in each prompt. The unavailable
web/database/platform matrix is outside these bounded connector tasks.

The existing offline Docker image, native binary, OAuth authorization and relay
are reused. Only public snapshots, ordinary project tests, prompts and tool
results reach the provider. Reference implementations and independent tests
remain outside model containers; grading occurs after verified process
termination. No provider quota polling, task retry, best-of selection or manual
intervention is allowed. Confirmed quota/refusal or unknown submission stops
scheduling and preserves the current slot. No Actions dispatch, merge, release
or user default change is part of the diagnostic.

`native-run.mjs` is an experiment launcher for ordinary native CLI sessions. B is
one automatic continuation, without a reviewer or another controller.
`run-comparison.mjs` retains every started slot, actual requests/usage, terminal
state and candidate archive. It accepts the existing external adapters; it does
not read authorization or launch paid work by import. Local launch wrappers and
private raw evidence remain under ignored `local/native-task-abc`.

`PREFLIGHT.json` records initial/reference observations. The initial API, legacy
migration and reconnect snapshots fail their new behavior cases; references pass.
The refactor preserves behavior on both sides and needs a separate structural
review. One original Windows-only test skips on Linux. For the intentionally
changed protocol API and revoked-auth behavior, the old superseded expectations
are adapted while retaining equivalent and surrounding assertions; they are not
counted as regressions to preserve.

Independent evaluation uses `evaluation-plan.json`, frozen test bytes and source
review of opaque assessment packets. It checks behavior, actual consumers,
regression substance, preserved assertions, docs and independently applicable
patches. Harness verdicts are reported separately. D0 and final patches are
retained for B and C, including improvements and regressions attributable to each
phase. All 12 slots, including unstarted slots if scheduling stops, must appear
in the final table. Actual time, requests and observed token usage are separate;
equal deadlines do not imply equal cost. No dollar bill is inferred from OAuth
usage and no next campaign is launched automatically.
