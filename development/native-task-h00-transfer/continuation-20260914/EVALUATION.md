The TTL installer adds a diagnostic method inside the pinned class solely to
clear expiry on an actually computed entry; it does not call set twice or alter
callbacks, value, maps or recency. This is a test-sensitivity instrument, not a
required implementation structure. The initial `missing-default-ttl-sensitivity`
mode used an extra set and could also change eviction. All six initial outcomes
are retained as superseded evidence, including an unrelated timing failure in
one control run; their nonzero exits are not relied on as isolated TTL evidence.
The refined check fails historical tests at their finite TTL bounds and controls
when an expired computed value is wrongly reused.

Other mandatory distinctions were checked by actual test content and, where
needed, existing narrow mutants. New denque rotate H00 misses nontrivial object
identity; P detects it but has a wrong README example. New removeWhere P misses
configured-capacity loss; H00 detects it. Both new onIdle suites detect early
resolution for an active worker on kill, but P omits queued-only kill and H00
omits active-worker killAndDrain/abort. Nonzero diagnostic exits were inspected
for relevant assertions, not treated as proof by themselves.

[Post-start observations](post-start-observations.json) separate resolved hypotheses
from actual defects and interpretations. Equivalent empty query encodings and
unspecified cross-generation callback ordering do not become artificial task
requirements. Both interpretations preserve the frozen evaluator and its raw
results. The four affected historical type/drain checks run only in new copies;
original Q/D and report files are unchanged. New calibration gaps are disclosed,
not used to declare reference/alternative fully sensitive.

## Evidence and limits

[Neutral quality decisions](neutral-quality-decisions.json) are byte-identical to
the saved pre-unblinding document; its [checkpoint](quality-decision-checkpoint.json)
contains SHA-256. Initial pending review text is historical context; top-level Q,
findings and assessmentNotes are the final decisions. The same assessor monitored
the schedule, so this is not independent double blinding.

[Evaluations](evaluations/) include final grades, scenario reviews, applicable patch
hashes, ordinary/original/interpreted checks, relevant diagnostic excerpts and
separate native/report evidence. [Verification](verification.json) accounts for
all 89 isolated project checks and proves local termination/container removal.
[Host type probes](normalized-context-types.json) and
[control/historical supplemental outcomes](supplemental-controls.json) retain
compact evidence and local full-output hashes. Original raw provider traces and
complete source copies remain private.

[Results](results.json) deliberately keep complete-series statistics null. The
unchanged frozen `statistics.mjs` rejects these incomplete rows; task means for
nine completed pairs are descriptive only. No full platform matrix or paid
reproduction was run for this report. Local artifact validation and any automatic
CI are separate evidence classes.

Report/source whitespace validation passes excluding archived `.patch` payloads.
The raw outer diff check exits 2 on preserved unified-diff context prefixes and
tab indentation; all warnings are confined to those payloads. Actual ordinary
source and terminal patch application succeeds. Payloads are not rewritten to
silence the outer diff check.
