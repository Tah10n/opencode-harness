# Frozen complete-task development comparison

This is a nine-run hypothesis check, not confirmatory evidence of statistical lift.
The three new tasks begin from public original trees: quick-lru take, denque drain,
and EventEmitter3 emitCollect. These tasks were specified before any outcomes;
no task is selected from a fresh plain failure, and none is replaced after outcomes.
Earlier removeWhere, rotate, computed/prune, prepend/remove-context tasks are not reused.

Order: quick-lru P/R/H; denque R/H/P; EventEmitter3 H/P/R. Each combination runs
once in a fresh container/session from the same task input and installed dependencies.
P has ordinary native tools. R uses direct+sensitivity and one general same-session
completeness pass. H uses direct+sensitivity with at most one optional same-model
focused investigator and no general extra pass. The author alone chooses whether
and what to investigate. H/R compares the organization package, not context isolation
alone. A never-used H capability remains an H outcome.

OpenCode 1.18.26, openai/gpt-5.6-luna/high for every measured role. Each whole task,
including R's second pass or H's child, has 900 seconds. The shared diagnostic budget
is 180 seconds per task. Equal deadline is not equal token budget. There are no real
smokes, retries or extra task-runs. Existing fail-closed transmission/unknown outcome,
authorization, quota, native stop and capture rules remain in force. Historical pauses
and campaigns are not resumed.

The task texts specify required behavior and delivered runtime/type/documentation
categories. Independent grading applies the same rubric to all terminal patches:

- Q: one applicable complete patch that meets the announced behavior, preserves the
  old API/tests, supplies meaningful tests in the announced categories, usable types
  and type-use regression, and usable public docs/example. Implementation shape is
  unrestricted. Hidden cases check contractual behavior; no assigned mutation or
  exact additional assertion is a required deliverable. Additional test quality is
  reported separately. Passing commands alone do not certify Q.
- T: normal autonomous native completion (`step_finish: stop` and normal exit), a
  captured applicable terminal patch, and verified process termination. An HTTP
  response, model summary or internal checks_passed status does not establish T.
- D = Q AND T. Internal incomplete is reported separately and does not define Q.

Before admission validate reference, a different valid implementation and substantive
wrong implementations against the independent behavioral evaluator. Reference is an
implementation under test, not a specification. Archive source/dependency/task,
runtime, rubric/evaluator and launcher hashes before the first real request. The
model sees only public task/source/tests, common project instructions, its own patch
and actual tool results. Never mount evaluator, calibration answers, other runs,
private sessions or credentials into a task container.

For H retain the pre-child implementation, child test patch, host-observed commands,
accept/decline rationale, and final patch. Attribute only actual new child work and
actual author tool checks. Report any integration regression. Grade anonymous patch
identities where feasible, then join arm labels. A three-task positive D balance vs
both controls with observed useful integration and no serious new regression is only
a practical signal; ties/losses keep complexity experimental. No follow-on series.

Account for every role/request with input+output tokens only (cache and reasoning
are nested subsets, not extra tokens); unknown usage stays unknown. Show native wall
time, summed request/stage costs and development/preparation/evaluator time separately.
No monetary price is inferred without a bill. Publish compact results, patches and
reproducible commands, never full dependency trees, raw sessions or credentials.
