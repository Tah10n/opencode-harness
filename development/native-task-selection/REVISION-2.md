# Acceptance before preference: development revision 2

This revision targets two observed selector failures: incomplete mandatory delivery accepted as relatively preferable, and research ending without a timely decision. It is one development revision on the same six known V3 pairs, not independent evidence of general harness lift. The historical series and its report remain in README.md/results.json; baseline selector source is retained in commit 25a6d4a2.

The original full task remains authoritative. Before ranking, the selector records concrete required behavior, preserved contracts, and explicitly delivered tests/docs for both candidates as confirmed, missing or unverified. In particular it must inspect the actual delivered consumer invocation and asserted case. Filled records and successful suites do not certify those judgments. The small decision reader checks only syntax and consistency, and always marks semantic validity unverified. A terminated answer that makes an inconsistent decision is retained without repair.

The same native launcher permits up to 240 seconds of research and 300 seconds overall. Bash timeouts reserve one second for native tool finalization. At the research boundary new tool admissions close; any outstanding provider request must settle before the launcher stops the research process and starts the preplanned tool-free decision stage in the **same native session**. No research-abort exception permits a new request with unknown provider state. A request still outstanding at the overall deadline remains a timeout. Early completed decisions finish immediately. An early research response without a decision can proceed to the planned final stage. There is no JSON repair, second judge, author repair, or merged patch.

The selection-only native plugin supplies separate HOME, TMPDIR and XDG directories according to each bash workdir, which must be /input/X, /input/Y, /input/base or the corresponding scratch root. One candidate is executed per call. Commands that explicitly override these variables or execute another candidate inside the same shell must be excluded as mixed diagnostics on inspection; this is not a new command parser or adversarial isolation system. Read-only mounts, no-network containers and input hashes remain unchanged. Native apply_patch uses a relative permission pattern for the already-authorized scratch directory. The final stage denies all permissions as well as disabling tools; OpenCode otherwise retains apply_patch from scratch edit permissions.

Local validation uses `node development/native-task-selection/verify-local.mjs` and the existing scripted preflight entry `node scripts/verify-native-container-preflight.mjs <fresh-output> --selection`. The scripted provider is an opt-in branch in the existing fixture, with no OpenAI calls. It verifies native scratch writes, real public-consumer commands in separate state, actual command output arriving in the final prompt, one native session, a request crossing the research boundary and settling before final, a tool-free final request, immutable inputs and process termination. Branch fixtures cover complete/incomplete/uncertain pairs, missing delivered consumer tests despite green suites, early completion, reserved final time, overall timeout, cancellation and unknown execution. Scripted answers establish control flow only.

One independent read-only review identified an unsafe research cancellation that could have continued with unknown provider state; it was fixed before freezing. The final delayed-request preflight passed in 23.860 seconds (6 scripted requests); the existing ordinary native-task preflight also passed (8 scripted requests). Earlier preparation failures are retained locally: missing explicit plugin loading, fixture model selecting a different native tool set, and apply_patch remaining available during final. All involved zero OpenAI calls and are not comparative evidence.

The six-run protocol retains OpenCode 1.18.26, openai/gpt-5.6-luna, high, one 300-second attempt per exact V3 pair, balanced neutral labels and the prior order. Preparation freezes prompt, source, patches, dependencies and executable revision before any provider request. No retries, prompt edits after results, new candidates, grader disclosure, manual Actions, platform matrix, merge, release or default change are authorized. Report usable patch delivery, correct rejection of incomplete pairs, and timely selection separately; retain selector-export sensitivity and the original dual-config contract. Candidate generation costs remain separate.
