# Conditional transfer, frozen before transfer outcomes

Use the same complete-delivery rubric as ../RUBRIC.md: behavior, preserved
contracts, meaningful delivered tests, types and documentation. Automated pass
alone is insufficient. Grade every patch, including timeout captures, and retain
both repetitions without selecting the better one. Handoff, claims, operational
failure and full S are separate.

H11 was selected from the primary six tasks by the predeclared rule: H01/H11
both S=6 and zero false full-delivery claims, H11 lower median full task wall
(317850.5 versus 346019 ms). P had S=3. H11 B feedback caused an immediate lint
repair; a unique A contribution or substantive A-to-B discovery chain was not
established. H00 also had S=6, so primary data does not establish an incremental
A/B quality improvement. This gate admits a small repeatability check, not a
claim of synergy or default promotion.

The original primary candidate is retained unchanged. Transfer uses the narrowly
corrected B diagnostic classifier (native timeout footer distinct from test text,
exit 0 authoritative); corrected installed fixtures passed with zero real model
requests. Pin corrected source/bundle before all eight transfer calls. No task
outcome may tune A, B, prompts, checks, or the other transfer task.

New projects were selected for the same public Node npm-library class and
executable environments, without any transfer P outcomes:

- p-debounce 5.1.1, 792115ea04019c720ddc8753010c758c55796f77:
  queued-call cancellation on pDebounce.promise, public callable/types/docs,
  exact reasons, active/queued boundaries, later queued execution and reuse.
- p-throttle 8.1.1, 09f6e9503dd590b9a3c9e33711ff65a23cf1032b:
  invocation receiver propagation into two option callbacks, weighted/windowed
  and strict scheduling, failure/bypass preservation, types and docs.

Each task has two fresh P/H11 pairs, balanced order: task one P,H11,H11,P;
task two H11,P,P,H11. Repetitions share a task contract but no execution state.
They are not independent new tasks. OpenCode 1.18.26, Luna/high, 900 seconds per
complete task. Exactly eight slots, no technical smoke or outcome retries.

Calibrate independent runtime/types on unchanged, reference, alternative and
specific wrong variants before freezing. Run the original project workflow on
baseline and formatted reference/alternative source/type overlays. Reference
controls establish rubric executability, not model quality. Inspect all author
regressions for the explicit state/assertion requirements in TASK.md; the
independent tests cannot certify those assertions. Keep any grader/control
preparation defects and unavailable checks visible.

Report per task/repetition and aggregate full patches, native handoffs, claims,
requests/tokens/unknown usage, total slot wall and component costs. Report the
two within-task repeats explicitly. A positive transfer balance would be a small
development signal only; ties or losses do not support general superiority.
No additional campaign or default promotion is authorized by this protocol.

Pre-freeze timing limitation: the formatted p-throttle alternative passed all
independent runtime/type checks but one broad project run failed the existing
`strict mode enforces spacing between saturated executions` and
`strict mode handles setTimeout drift` wall-clock assertions. Baseline and reference
broad runs passed; one focused baseline/alternative comparison of exactly those
tests passed on both sides. Their unweighted, callback-free scheduler paths are
unchanged by the reference/alternative. Preserve that failed full run; do not call
it a broad pass. No assertion or timing threshold was changed.

For either arm, a project failure is not automatically a product regression or
an environment exemption. If one of these exact old timing cases fails during
grading, retain the first broad outcome, inspect the patch for scheduler/test
changes and perform at most one bounded baseline/candidate focused comparison.
Only classify it as baseline/timing noise with reproduced baseline failure or
verified unchanged execution path plus the focused same-command comparison;
otherwise preservation is unproven (S=0). New failing cases receive ordinary
contract diagnosis, not this exception. Never rerun the model or keep only a
passing project result. Always report first broad pass/failure separately from S.
