# Support URLSearchParams through UFO's query consumers

Callers that already hold URLSearchParams should not need to collapse repeated keys into an object. Add URLSearchParams input support to the public stringifyQuery API, withQuery helper and the existing $URL.query property. Preserve existing object-input behavior and API compatibility.

For URLSearchParams, stringifyQuery emits all entries in their iteration order, including repeated/interleaved keys and empty values, using UFO's existing query key/value escaping. An empty value from URLSearchParams is represented as `key=`. Do not mutate the input. Empty params serialize to the empty string. Unicode, spaces, plus signs, delimiters and encoded percent signs must round-trip through parseQuery consistently with the existing encoding rules.

withQuery(url, params) replaces all existing occurrences of every key present in params, preserves all other existing keys/values, then appends the supplied entries in their iteration order. Keep path, fragment and authority intact. Empty params preserve the query's existing meaning; object callers keep their current merge/removal behavior (including undefined, null, false, 0 and arrays). No caller-owned object or params may be mutated.

A caller may assign URLSearchParams to an existing $URL instance's query property. Its search, fullpath, href, toString and searchParams must represent those entries faithfully. searchParams returns an independent native URLSearchParams, so mutating that result does not change the $URL. Existing plain-object query behavior is preserved. $URL.append must continue its existing overlay semantics when the receiving query is URLSearchParams: the appended URL's query keys replace the receiving occurrences, unrelated receiving entries survive, and paths/hashes retain the preexisting append behavior. This is support for the already exported class, not a new wrapper or consumer.

Update public TypeScript types so these usages typecheck while preserving QueryObject compatibility. Deliver project regressions through the public entry points for duplicate/interleaved/empty/escaped values, withQuery overlay and path/fragment preservation, class serialization and detached searchParams, append into params-backed query, no input mutation, and existing object edge cases. Include a type-level usage regression and update user-facing docs/examples. No specific helper implementation, test filename or exception subtype is required. Run the existing test/lint/typecheck/build checks relevant to this project after the last change. Keep dependencies and existing tests. Do not use another attempt's implementation or introduce a new dependency.
