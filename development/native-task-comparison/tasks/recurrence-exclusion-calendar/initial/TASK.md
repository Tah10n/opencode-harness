# recurrence-exclusion-calendar

Implement occurrences(start,end,weekdays) using UTC dates with start inclusive/end exclusive, selecting each matching weekday once even if weekdays contains duplicates. Integrate calendar(rule) where rule={start,end,weekdays,exclude,replace}: exclude suppresses an original date before replacement, including when a replacement exists. replace maps original dates to replacement dates; keys not generated by the recurrence are ignored. Return {original,date} records sorted by output date then original date in lexicographic order; retain two distinct occurrences moved to the same date. Domain: valid dates YYYY-MM-DD from 2000..2099, start<=end, weekday integers 0..6, finite arrays and plain own-data replace dictionary. Replacement dates may fall outside recurrence bounds. No host timezone dependence or input mutation. Preserve basic daily UTC results.

Preserve existing public behavior and all old test coverage. Use only Node built-ins; do not add dependencies. Inputs outside the explicitly stated domain need not be accepted. Implement the change through the existing public entry points.

Add project regression tests (any test names are acceptable) that demonstrate:
- Weekday selection with duplicate weekday and exclusion that also has a replacement.
- Replacement outside bounds with deterministic output ordering.

Update project documentation to explain:
- UTC, half-open date range and original-date exclusion precedence.
- Distinct occurrences may share a replacement date; output sort and ignored unused replacement keys.
