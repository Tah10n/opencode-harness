# Durable delivery outbox upgrade
A desktop app must retain queued notifications until the receiver explicitly acknowledges them.
1. Existing files contain a legacy array `{id,payload}`. loadQueue(file) must return v2 `{version:2, pending:[{id,payload,attempts}], delivered:[id...]}`. Legacy items start with attempts 0 in original order. v2 must round-trip payloads and delivered history without mutation. IDs must be unique nonempty strings across pending and delivered; attempts must be nonnegative integers. Reject unknown versions or malformed state with TypeError. A missing file yields empty v2; other read/parse errors propagate.
2. flush(file, send) processes a snapshot of pending IDs sequentially. For each item call await send(payload, id). Only a response with `ack === id` removes that pending item and appends the ID once to delivered. A rejected promise, missing response, or mismatched ack retains it and increments attempts exactly once. Continue after those delivery failures. Preserve pending order and prior delivered IDs.
3. Persist state atomically after EACH attempted delivery, before starting the next. If persistence fails, stop and reject rather than claiming successful flush. Return `{delivered: countAcknowledgedThisFlush, pending: remainingCount}`. Retry with a fresh load must not resend IDs already persisted as delivered.
4. Legacy load alone does not rewrite the file. Invalid state must never be overwritten. No concurrent writers are required for this task.
5. Add project tests for mixed ack/reject/mismatch, restart retry, legacy migration, invalid state, and a persistence failure stopping the next send. Preserve old test coverage. Document acknowledgment and per-attempt persistence in README.md.
