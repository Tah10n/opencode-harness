# Lazy pagination with compatible eager export
A catalog CLI needs streaming iteration, while existing callers still need the eager list.
1. Add exported async generator `iterateItems(fetchPage, {signal} = {})`. Fetch first page with `fetchPage(undefined, {signal})` only when iteration first advances. Each response is `{items: array, nextCursor?: string|null}`. Yield items in order; fetch the next page only after all items in the current page have been consumed. Breaking the loop early must not fetch another page.
2. Missing/null nextCursor ends iteration. A nonempty string continues, including across empty pages. A repeated continuation cursor, empty string cursor, non-array items or non-object page rejects with TypeError. Detect repeated cursor before making a repeated fetch request. Do not mutate responses or arrays.
3. Before each fetch and before yielding each item, an aborted signal throws its reason (or AbortError when reason is absent). Forward the exact signal to fetchPage. Do not initiate a fetch on an already aborted signal.
4. Preserve `listItems(fetchPage)` as an eager array promise and extend it to accept the same options by consuming iterateItems. Preserve errors from fetchPage. Update the existing `exportNames(fetchPage, options?)` consumer to support cancellation and the same complete ordered items, retaining one name per line and a trailing newline only for nonempty results.
5. Add project tests of lazy/early-break behavior, empty intermediate pages, repeated cursor, signal identity and abort between yielded items, and both eager/consumer paths. Keep old tests. Document lazy versus eager semantics and cancellation in README.md.
