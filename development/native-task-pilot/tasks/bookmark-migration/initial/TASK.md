# Upgrade bookmark storage safely
The bookmarks app must read a versioned v2 store without losing existing user data.
1. load(file) continues accepting legacy `{version:1, bookmarks:[{url,title,tags?}], ...metadata}`. Return v2 `{...metadata, version:2, bookmarks:[{id,url,title,tags}], nextId}`. Assign `b1`, `b2`, ... in original array order, including duplicate URLs. Missing tags becomes []; preserve existing string tags, titles, Unicode URLs and unknown top-level metadata.
2. A valid v2 input is returned without ID reassignment or data loss. v2 IDs are nonempty unique strings; nextId is a positive integer strictly greater than every numeric bN ID. Reject unknown versions, non-array bookmarks, malformed entries, duplicate IDs, invalid tags and invalid nextId. Legacy URL/title must be strings and URL nonempty; tags if supplied must be an array of strings. Throw TypeError for structurally invalid parsed data; malformed JSON and filesystem read errors propagate. Tags may be omitted in either version and normalize to [].
3. load is read-only: neither valid legacy migration nor invalid input rewrites the file. save(file, state) validates/normalizes before its existing atomic write; invalid input preserves the original bytes. Calling save with loaded legacy data persists v2. Do not mutate caller objects.
4. listTitles(file) remains a working consumer of both versions and preserves order/duplicate titles.
5. Add migration, validation, byte-preservation, round-trip and consumer project tests. Keep old tests. Document v1-to-v2 rules and read-only load in README.md.
